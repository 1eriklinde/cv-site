The slowest part of changing this page from a phone is typing the sentence that describes the change.

The laptop is optional now: the repository, the tests, the preview and the deploy are all URLs. A change described on a train is staged at its own address within a minute, and goes live everywhere the moment you look at it and accept it. $ cat from-a-phone.md

1Say what to change. Open Claude Code in the browser on the phone, point it at this repository, and describe the edit in a sentence — shorten the summary, add a role, fix a date, change the accent colour.
2It edits and pushes. The change lands in index.html and goes to main as an ordinary commit. Nothing about the repository is phone-specific; it is the same push I would make from a keyboard.
3The tests run. GitHub Actions runs the same test suite on a free runner. A failure stops there and nothing reaches the site — which matters more, not less, when the person pushing is on a train and cannot see the page.
4A preview appears. A passing run uploads the build as a new version with its own URL. Production carries on serving the old page — nothing anyone else can see has changed. Open the preview on the phone and look at what you actually made.
5You accept it. Approving the deployment promotes that exact version to the edge, and about fifteen seconds later it is live in every region. Nothing reaches the public page without someone looking at it first — which is the part that makes doing this from a train reasonable rather than reckless.
from nothing
Someone starting with only a phone needs three free accounts — GitHub, Cloudflare, Claude — and a browser. No terminal, no laptop, no card. Cloudflare's CLI login even has a device flow that hands you a short code to type into the dashboard, which is exactly the shape of thing a phone handles well.
the one catch
The deploy key has to be minted in a browser, once: wrangler's OAuth scopes cannot create API tokens, so that single step is a visit to the Cloudflare dashboard. Until it exists the pipeline still runs the tests and simply skips the deploy. After it exists, the loop is closed.
why it holds up
Because this is plain files with no build step: nothing to compile, no toolchain to install, no lockfile to reconcile. The tests finish in about a second and the upload takes fifteen. There is no step in the middle for a phone to be bad at.
